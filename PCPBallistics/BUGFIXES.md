# PCP Ballistics コードレビュー / 修正内容

`ContentView.swift` の弾道計算ロジックを検証し、以下を修正しました。

## 物理・計算のバグ

| # | 内容 | 修正前の症状 |
|---|------|-------------|
| 1 | 縦風の扱いが逆 | `vRelative = v0 + headWind` を「対地の初速」として時間計算に使っていたため、**向かい風で飛行時間が短く**、追い風で長くなっていた。修正版は気団基準で `s = 射距離 + 向かい風 × t` を反復計算し、対気初速で減速させる |
| 2 | 空気抵抗を水平距離で計算 | 打ち上げ／打ち下ろし時に弾が実際に飛ぶ距離（直線距離）より短い距離で減速を計算していた。直線距離ベースに変更し、重力落下のLOS直交成分に `cos(角度)` を掛ける（改良ライフルマンルール） |
| 3 | MIL値の除数が水平距離 | MILは照準線（直線距離）に対する角度なので、角度がつくと補正量が過大になっていた。直線距離基準に修正 |
| 4 | 横風の符号が逆 | 3時（右）からの風は弾を**左**へ流すが、正の値として返していた。`+ = 右へ流される` に統一し、流され方向と補正（ダイヤル）方向をUIに表示 |
| 5 | ゼロイン時の仰角に風を含めていた | 銃身の仰角は機械的に固定なので、ゼロインは無風・水平で取った前提で計算するよう変更 |
| 6 | 抗力定数の校正不足 | `k = 0.00004 / BC` は減速が小さすぎ（100mで速度低下8%程度）、100mのドロップを3割ほど過小評価していた。`0.0001 / BC` に変更（**要実射校正**、下記参照） |
| 7 | ゼロイン距離0で0除算 | `zeroAngle` が inf → 表示が `nan`。計算不能として `—` を表示 |
| 8 | 気温入力に `.decimalPad` | マイナス記号が入力できず氷点下の気温を設定できなかった。`.numbersAndPunctuation` に変更 |

## UIの修正

- 補正値に**方向（上／下・左／右）**を表示。数値だけでは逆にダイヤルする危険があった
- 入力が不正なときに `0.0 cm` ではなく `—` を表示
- グラフの描画範囲が10〜100mでスライダーは120mまでだったため、遠距離でターゲット線がグラフ外に出ていた。両方を120mに統一
- 飛行時間を表示

## 重要: 抗力定数の校正について

`BallisticCalculator.dragConstant` は指数減速モデルの経験定数です。実測ドロップに合わせて必ず調整してください。

- 50mゼロ・実測より**ドロップが小さすぎる** → 値を大きく（例: 0.00012）
- **ドロップが大きすぎる** → 値を小さく（例: 0.00008）

指数減速モデルはG1などの抗力曲線の近似なので、100mを超えると誤差が増えます。実射での確認を前提に使ってください。

## 未対応（仕様判断が必要）

- `weightGrains` は計算に使われていません（弾重の影響はBCに含まれるため）。着弾エネルギー表示に使うか、引数から外すか要判断
- ゼロイン時の気圧・気温を入力できないため、現地条件でゼロイン仰角を再計算しています（通常は誤差小）
- スピンドリフト、エアロダイナミックジャンプ、上下風は未考慮
